## 📄 응원 멘트 자동 발송 시스템 (Coach Intervention System) 기술 명세서
**문서 버전:** v1.0 (현빈 검토 완료)
**작성 목적:** 학습자의 몰입도 저하, 지루함, 또는 학습 성과 하락 시점을 데이터 기반으로 감지하고, 적절한 타이밍에 맞춤형 응원 멘트를 발송하여 사용자 경험을 극대화한다.

### 1. 핵심 KPI 및 트리거 정의 (Trigger Definition)

| 구분 | 목표/측정 대상 | 측정 지표 (KPI) | 임계값(Threshold) & 조건 (Condition) |
| :--- | :--- | :--- | :--- |
| **몰입도 저하** (Attention Gap) | 집중력 유지, 활동성 | 1. 응시 이탈 빈도 (Gaze Deviation Frequency) | 30초 동안 화면 외 영역을 반복적으로 주시하거나, 시선 이동 패턴이 불규칙할 때 $\text{Frequency} > N$ |
| | | 2. 발화 간격 지속 시간 (Sustained Pause Time) | 연속으로 **4~8초** 이상의 긴 침묵 또는 응답 지연 발생 시 |
| **학습 성과 하락** (Performance Dip) | 문법/발음 정확도 | 1. 오류율 급증 (Error Rate Spike) | 특정 유형의 질문이나 패턴에서 **3회 이상 연속으로 오류**를 범했을 때 $\text{Rate} > 0.7$ (이전 평균 대비) |
| | | 2. 답변 길이 감소 (Reduced Complexity) | 이전 세션 대비 사용자가 사용하는 문장 구조가 단순화되거나, 핵심 어휘 활용 빈도가 현저히 낮을 때 |
| **참여 부족** (Engagement Loss) | 적극적인 참여 유도 | 1. 응답 시도 지연 시간 (Initial Response Latency) | 질문에 대한 첫 발화 시도가 **7초 이상** 지연될 경우 |

### 2. 필수 데이터 필드 및 로깅 스키마 설계 (Data Schema for Kodari)

이 데이터를 실시간으로 수집하고, 이벤트를 기반으로 분석하는 시스템을 구축해야 합니다. 아래 필드는 `User_Interaction_Event` 테이블에 포함되어야 합니다.

| 필드명 | 자료형 | 설명 | 데이터 유형/예시 | 로깅 필요성 |
| :--- | :--- | :--- | :--- | :--- |
| **event\_id** | UUID | 이벤트 고유 식별자 (Primary Key) | `uuid-v4` | 필수 |
| **user\_id** | String | 사용자 ID | `student_A123` | 필수 |
| **session\_id** | String | 세션 고유 ID | `sess_20260515T1030` | 필수 |
| **timestamp** | Timestamp | 이벤트 발생 시간 (UTC 기준) | `2026-05-15 10:30:45` | 필수 |
| **activity\_type** | Enum | 현재 활동 유형 | `speaking_practice`, `grammar_drill`, `free_talk` | 필수 |
| **kpi\_score** | Float | 해당 시점의 측정 KPI 값 (0.0 ~ 1.0) | `0.65` (예: 발음 정확도 점수) | 필수 |
| **behavior\_metric** | JSON/Map | 행동 지표 상세 로깅 (기술적 데이터 포함) | `{ "gaze_deviation": 0.8, "pause_sec": 7.2 }` | 필수 |
| **trigger\_condition** | Boolean | 위 정의된 트리거 조건 중 충족 여부 | `True`/`False` | 핵심 로직 |
| **severity\_level** | Enum | 문제의 심각도 (시스템 내부 판단) | `Low`, `Medium`, `High` | 필수 |

### 3. 응원 멘트 발송 흐름 설계 (Intervention Flowchart Logic)

응원 멘트는 무작위로 보내는 것이 아니라, **'문제 발생 $\rightarrow$ 심각도 분석 $\rightarrow$ 최적의 메시지 선택 $\rightarrow$ 전달'** 단계를 거쳐야 합니다.

1.  **데이터 수집 및 모니터링:** (Kodari 역할)
    *   사용자 행동 데이터가 실시간으로 `User_Interaction_Event` 테이블에 로깅된다.
2.  **트리거 감지 (Detection):**
    *   시스템이 1단계에서 정의된 임계값을 초과하는 이벤트를 감지하고, 해당 이벤트의 $\text{trigger\_condition}$을 `True`로 설정한다.
3.  **심각도 분석 및 우선순위 부여 (Analysis):**
    *   트리거가 발생하면 **KPI 점수 하락(성능)** > **긴 침묵(몰입도)** > **잦은 이탈(집중력)** 순으로 심각도를 결정한다. (`High` = 성능 + 몰입도 동시 급하락)
4.  **멘트 매칭 및 발송 (Action):**
    *   시스템은 `severity_level`과 `activity_type`에 따라 가장 효과적인 응원 멘트 카테고리(예: "기술적 지지", "심리적 격려")를 선택하고, 미리 준비된 템플릿에서 내용을 조합하여 사용자에게 전달한다.
