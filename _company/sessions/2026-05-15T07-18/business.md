## 🎯 목표 정의 및 비즈니스 가치

**목표:** 서비스 런칭 직후, 초기 마케팅 활동의 효율성(CAC)과 고객 유지력(LTV)을 실시간으로 측정하여, LTV:CAC 비율이 최소 3:1 이상이 되도록 운영 전략을 수립한다.
**사용 부서:** 마케팅팀, 경영지원팀 (데이터 분석 담당)
**필요 시스템 기능:** CRM 연동 기반 사용자 데이터 필드 추가 및 API 엔드포인트 설계

## 📊 핵심 지표 정의 및 계산 로직

### 1. 고객 확보 비용 (CAC: Customer Acquisition Cost)
*   **정의:** 신규 유료 고객 한 명을 확보하는 데 들어간 총비용.
*   **계산 공식:** $\text{총 마케팅/판매 비용} / \text{신규 가입 유료 사용자 수}$

| 필드명 (DB Field) | 데이터 타입 | 설명 | 계산 로직 | 측정 주기 | 비고 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `mktg_spend_total` | Decimal | 광고 플랫폼(YT, IG 등) 지출 총액 | (광고비 + 콘텐츠 제작 외주비 + 인건비 할당분)의 누적 합계 | 일별/월별 | 필수: 지출 증빙 기반 |
| `new_paid_user_count` | Integer | 해당 기간 내 유료 결제 첫 기록을 남긴 신규 사용자 수 | 1. 회원가입일 기준 필터링 $\cap$ 2. 최초 결제 발생 여부 플래그 (True) | 일별/월별 | |
| **CAC** | Decimal | N/A | `mktg_spend_total` / `new_paid_user_count` | 실시간 계산 | 목표: 낮게 유지 |

### 2. 고객 생애 가치 (LTV: Lifetime Value)
*   **정의:** 한 명의 사용자가 우리 서비스에 존재하는 전 기간 동안 창출할 것으로 기대되는 총수익.
*   **계산 공식:** $\text{평균 사용자당 매출} / \text{월별 이탈률}$

| 필드명 (DB Field) | 데이터 타입 | 설명 | 계산 로직 | 측정 주기 | 비고 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `user_id` | String | 사용자 고유 식별자 (Primary Key) | N/A | N/A | CRM 연동 필수 |
| `initial_plan_tier` | Enum | 최초 가입 시 선택한 유료 플랜 레벨 | 결제 기록 테이블 (`payment_history`)에서 추출 | 1회성 | 예: BASIC, PREMIUM |
| `total_revenue` | Decimal | 해당 사용자가 서비스 이용 기간 동안 발생시킨 총매출액 (환불 제외) | 결제 이력 테이블의 매출 합계 ($\sum$ Payment Amount) | 누적/월별 | 환불(Refund)은 마이너스로 처리 |
| `churn_date` | Date | 사용자가 서비스를 최종적으로 사용하지 않은 날짜 | 마지막 로그인 또는 활동일로부터 30일 이상 경과 시점 | N/A | LTV 계산에 핵심 변수 |
| **LTV** | Decimal | N/A | (총 매출액 / 총 사용자 수) $\times$ 평균 유지 기간 예측치 | 실시간 근사치 | 목표: 높게 유지 |

## 💻 개발팀 실행 명세 (Technical Specification)

### 1. 데이터베이스 요구사항
*   **테이블 추가:** `user_metrics` 테이블 신설 및 다음 필드 포함:<br>
    *   `user_id` (PK)<br>
    *   `first_paid_date` (Date)<br>
    *   `last_activity_date` (Timestamp)<br>
    *   `total_revenue` (Decimal)
*   **API 엔드포인트:** `/api/v1/kpi/lca/{user_id}`: 특정 사용자 ID를 통해 현재 LTV 및 활동 상태를 조회하는 API 구축.

### 2. 로직 구현 우선순위 (MVP 기준)
1.  **[High] CAC 계산 파이프라인:** 매일 새벽 0시, 전날의 마케팅 지출 데이터를 취합하여 `mktg_spend_total`을 업데이트하고, 신규 결제 사용자 수와 나누어 **데일리 CAC 값**을 DB에 기록하는 Batch Job 구축.
2.  **[High] LTV 트래킹:** 결제 발생 시점마다 `user_metrics.total_revenue` 필드를 즉시 업데이트 (Write Trigger).
3.  **[Medium] Retention/Churn 측정:** 사용자 활동(로그인, 핵심 기능 사용) 이벤트를 기반으로 `last_activity_date`를 최신화하고, 30일 이상 공백 발생 시 '이탈 위험군' 플래그 부여 로직 구현.
